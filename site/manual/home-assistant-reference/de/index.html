14. Home Assistant: Entitäten, Dienste, Ereignisse, Assist

Inhalt

Alles, was PadSpan Home Assistant für Automationen, Skripte, Dashboards und Assist gibt. Die Tabellen entstehen mit scripts/build_manual_reference.py aus PadSpans Code, und ein Test schlägt fehl, wenn sie und der Code nicht übereinstimmen. Sie beschreiben also die Version, mit der sie ausgeliefert werden.

Wie Entitäten benannt werden

PadSpan legt Entitäten nur für Geräte an, die du in PadSpan benannt hast (ein Name an einer Bluetooth-Adresse, ein Handy oder eine Uhr, benannt über seinen Schlüssel, oder ein iBeacon). Die Tausenden unbenannten Geräte, die ein Haus hört, bekommen keine.

Jedes benannte Gerät ist in Home Assistant ein Gerät mit dem Namen, den es in PadSpan hat. Seine Entitäten bekommen ihre IDs aus diesem Namen, so wie Home Assistant es immer macht: kleingeschrieben, Leerzeichen und Satzzeichen als _. Ein Tag namens „Car keys“ bekommt device_tracker.car_keys, sensor.car_keys_area und sensor.car_keys_distance. Ist eine ID schon vergeben, hängt Home Assistant _2 an. Du kannst eine Entität in Home Assistant umbenennen; PadSpan folgt ihr über ihre eindeutige ID, nicht über ihren Namen.

Welche Arten von Entitäten PadSpan anlegt, stellst du unter Verwalten → HA Entities → Entity Publishing Controls ein: Der Tracker, der Bereichssensor, der Entfernungssensor und die Entfernungssensoren pro Empfänger sind an, bis du ihr Häkchen wegnimmst; der Belegungssensor und die Teilzonen sind aus, bis du sie anhakst. Eine Art ohne Häkchen ist im Entitätsregister von Home Assistant deaktiviert, und wieder angehakt kommt sie zurück. PadSpan muss neu laden, bevor eine neu angehakte Art für Geräte erscheint, die es schon hat.

„In HA's history“ in den Tabellen sagt, ob die Datenbank von Home Assistant dieses Attribut behält. Die, die sich mit jeder Abfrage ändern (etwa alle 5 Sekunden), wie rssi und age_s, bleiben aus der Datenbank heraus, damit sie klein bleibt. Sie stehen trotzdem an der Entität, Automationen und Templates können sie also lesen.

<device> steht für den ID-Teil des Geräts, <receiver> für den Empfänger, wie PadSpan ihn nennt, und <sub-zone> für den Namen der Teilzone.

Dienste

Die folgenden Tabellen sind englisch: Sie entstehen direkt aus PadSpans Code.

padspan_ha.set_room_tag_map: Set Room Tag Map

Replace the curated room_tag_map (room name → list of object keys). Persisted across restarts.

FieldRequiredTakesDefaultWhat it does
room_tag_mapyesa mappingRoom name → list of PadSpan object keys. Replaces the whole map.

padspan_ha.dump_devices: Dump Devices

Returns all tracked BLE devices with current room, RSSI, age, and smoothing state. Equivalent to Bermuda BLE Trilateration dump_devices service. Supports response data for use in templates, scripts, and automations. Also creates a persistent notification.

FieldRequiredTakesDefaultWhat it does
notifynotrue or falsetrueCreate a persistent notification summary in HA (default true).

padspan_ha.wled_on: WLED on with its look

Turns WLED lights on with the look PadSpan remembered for them (every part, colour, white, effect and brightness), exactly and with no flash. A light PadSpan doesn't run is turned on by Home Assistant as usual.

Target: light entities of the wled integration.

FieldRequiredTakesDefaultWhat it does
brightness_pctnonumber, 1 to 100 %Brightness in percent. Leave empty for the remembered brightness.
transitionnonumber, 0 to 300 sFade time in seconds. Leave empty for the remembered fade.

padspan_ha.wled_off: WLED off

Turns WLED lights off the way PadSpan does: only the light as a whole goes off, so its remembered look is there the next time it comes on.

Target: light entities of the wled integration.

FieldRequiredTakesDefaultWhat it does
transitionnonumber, 0 to 300 sFade time in seconds. Leave empty for the remembered fade.

padspan_ha.dump_devices kann seine Liste an den Aufrufer zurückgeben: Gib der Aktion in einem Skript eine response_variable und lies daraus devices (die Daten jedes Geräts, unter PadSpans Schlüssel dafür), count, version und timestamp. Mit notify: false gibt er nur die Liste zurück.

padspan_ha.set_room_tag_map speichert eine Liste, welche PadSpan-Objekte in welchen Raum gehören. PadSpan vergleicht sie mit dem, was es gerade hört, und zeigt die fehlenden. Die meisten Haushalte brauchen das nie.

Ist Tag-Ereignisse bei Raumwechsel an, kommt jedes padspan_room_change auch als eigener Auslöser Tag von Home Assistant: PadSpan meldet einen Tag-Scan mit der Tag-ID padspan_… für dieses Gerät. Die IDs stehen auf der Karte dazu unter Einstellungen → Ortung → Home Assistant und Integrationen, bei HA-Tags-Integration. Home Assistant nimmt jeden solchen Tag in seine Liste der Tags auf.

Assist: „In welchem Raum ist Alex?“

Das eigene Assist von Home Assistant beantwortet „Wo ist Alex?“ für eine Person, und eine Person übernimmt den Raum von einem PadSpan-Tracker nur, wenn kein anderer Tracker dieser Person mehr sagt: Das GPS eines Handys oder das „zu Hause“ eines Routers gewinnt. Für eine Antwort, die immer den Raum nennt, bringt PadSpan einen eigenen Intent mit. Er tut nichts, bis du Sätze dafür hinzufügst. Speichere das hier als config/custom_sentences/en/padspan.yaml und starte Home Assistant neu (oder lade es auf der Debug-Seite von Assist neu):

language: "en"
intents:
  PadSpanWhereIs:
    data:
      - sentences:
          - "which room is {padspan_person} in"
          - "what room is {padspan_person} in"
          - "where in the house is {padspan_person}"
lists:
  padspan_person:
    wildcard: true

Das Folgende ist englisch: Es entsteht direkt aus PadSpans Code.

Intent: PadSpanWhereIs. Slots: padspan_person, name.

What it answers, in English:

  • "I don't know anyone called <name>."
  • "<name> is away."
  • "I don't know which room <name> is in right now."
  • "<name> is probably in the <room>."
  • "<name> is in the <room>."

"probably" when the room's room_confidence is under 0.5.

Der Name ist der PadSpan-Name des Geräts („Alex“). Er passt auch zu einem Namen, der damit anfängt („Alex's Phone“, „Alex Watch“); passen mehrere, nimmt er das Gerät, das zuletzt gehört wurde. Du musst Assist nichts freigeben. Der Intent liest nur PadSpans aktuellen Raum und ändert nichts. Die Antworten sind auf Englisch. Mehr dazu, was die eigenen Sätze von Home Assistant tun: Assist fragen, wo jemand ist.

MQTT (experimentell)

Ist Enable experimental MQTT publishing angehakt (Verwalten → HA Entities → MQTT Publishing; aus, bis du es anhakst) und die MQTT-Integration von Home Assistant eingerichtet, veröffentlicht PadSpan außerdem jedes benannte Gerät nach jeder Abfrage, mit Retain. Hier ist <device> der Name, kleingeschrieben, mit Leerzeichen als _. Die Topics können sich in einer späteren Version ändern.

Drei Automationen

Jede ist eine ganze Automation: Füg sie in einer neuen Automation unter In YAML bearbeiten ein. Die Namen sind Beispiele; nimm deine eigenen Entitäts-IDs.

Ein Licht an, wenn Alex in die Küche kommt, nur wenn PadSpan sich des Raums ziemlich sicher ist:

alias: Kitchen light for Alex
trigger:
  - platform: state
    entity_id: sensor.alex_phone_area
    to: Kitchen
condition:
  - condition: numeric_state
    entity_id: sensor.alex_phone_area
    attribute: room_confidence
    above: 0.6
action:
  - action: light.turn_on
    target:
      entity_id: light.kitchen

Der Zustand ist der Name des Raums, wie Home Assistant ihn hat, mit seinen Großbuchstaben.

Ein Hinweis, wenn die Autoschlüssel das Haus verlassen:

alias: Car keys left
trigger:
  - platform: event
    event_type: padspan_device_departed
    event_data:
      label: Car keys
action:
  - action: notify.notify
    data:
      message: "The car keys have left the house."

Das Ereignis kommt, sobald die Schlüssel so lange wie das Abwesenheits-Timeout nicht gehört wurden (5 Minuten, wenn du es nicht unter Einstellungen → Ortung → Räume und Zeiten → Zuhause/Abwesend-Timeout geändert hast).

Die Alarmanlage scharf schalten, solange der Urlaubsmodus (Vacation Mode) läuft:

alias: Alarm with Vacation Mode
trigger:
  - platform: state
    entity_id: binary_sensor.padspan_vacation_mode
    to: "on"
action:
  - action: alarm_control_panel.alarm_arm_away
    target:
      entity_id: alarm_control_panel.house
