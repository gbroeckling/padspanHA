14. Home Assistant: entities, services, events, Assist

Contents

Everything PadSpan gives Home Assistant to use in automations, scripts, dashboards and Assist. The tables are made from PadSpan's code by scripts/build_manual_reference.py, and a test fails when they and the code disagree, so they describe the version they ship with.

How entities are named

PadSpan makes entities only for devices you have named in PadSpan (a label on a Bluetooth address, a phone or watch named through its key, or an iBeacon). The thousands of unnamed devices a house hears get none.

Each named device is a Home Assistant device with PadSpan's name for it. Its entities take their ids from that name the way Home Assistant always does: lower case, with spaces and marks as _. A tag named "Car keys" gets device_tracker.car_keys, sensor.car_keys_area and sensor.car_keys_distance. If an id is already taken, Home Assistant adds _2. You can rename an entity in Home Assistant; PadSpan follows it by its unique id, not its name.

Which kinds of entity PadSpan makes is set in Manage → HA Entities → Entity Publishing Controls: the tracker, the area sensor, the distance sensor and the per-receiver distance sensors are on unless you untick them; the occupancy sensor and sub-zones are off unless you tick them. An unticked kind is disabled in Home Assistant's entity registry, and ticked again it comes back. PadSpan must reload before a newly ticked kind appears for devices it already has.

"In HA's history" in the tables says whether Home Assistant's database keeps that attribute. The ones that change with every poll (about every 5 seconds), such as rssi and age_s, are left out of the database to keep it small. They are still on the entity, so automations and templates can read them.

<device> stands for the device's id part, <receiver> for the receiver as PadSpan names it, and <sub-zone> for the sub-zone's name.

Services

padspan_ha.set_room_tag_map: Set Room Tag Map

Replace the curated room_tag_map (room name → list of object keys). Persisted across restarts.

FieldRequiredTakesDefaultWhat it does
room_tag_mapyesa mappingRoom name → list of PadSpan object keys. Replaces the whole map.

padspan_ha.dump_devices: Dump Devices

Returns all tracked BLE devices with current room, RSSI, age, and smoothing state. Equivalent to Bermuda BLE Trilateration dump_devices service. Supports response data for use in templates, scripts, and automations. Also creates a persistent notification.

FieldRequiredTakesDefaultWhat it does
notifynotrue or falsetrueCreate a persistent notification summary in HA (default true).

padspan_ha.wled_on: WLED on with its look

Turns WLED lights on with the look PadSpan remembered for them (every part, colour, white, effect and brightness), exactly and with no flash. A light PadSpan doesn't run is turned on by Home Assistant as usual.

Target: light entities of the wled integration.

FieldRequiredTakesDefaultWhat it does
brightness_pctnonumber, 1 to 100 %Brightness in percent. Leave empty for the remembered brightness.
transitionnonumber, 0 to 300 sFade time in seconds. Leave empty for the remembered fade.

padspan_ha.wled_off: WLED off

Turns WLED lights off the way PadSpan does: only the light as a whole goes off, so its remembered look is there the next time it comes on.

Target: light entities of the wled integration.

FieldRequiredTakesDefaultWhat it does
transitionnonumber, 0 to 300 sFade time in seconds. Leave empty for the remembered fade.

padspan_ha.dump_devices can return its list to the caller: in a script, give the action a response_variable and read devices (each device's data, by PadSpan's key), count, version and timestamp from it. With notify: false it only returns the list.

padspan_ha.set_room_tag_map stores a list of which PadSpan objects belong in each room. PadSpan compares it with what it hears now and shows the missing ones. Most homes never need it.

Each one can trigger an automation (Event trigger, with the event type below). They fire only for devices you have named.

With Room-change tag events on, each padspan_room_change also comes as Home Assistant's own Tag trigger: PadSpan reports a tag scan with the tag id padspan_… for that device. The ids are listed on that card in Settings → Tracking → Home Assistant and integrations, under HA Tags Integration. Home Assistant adds each such tag to its Tags list.

Assist: "which room is Alex in?"

Home Assistant's own Assist answers "where is Alex?" for a person, and a person takes the room from a PadSpan tracker only when no other tracker on that person says more: a phone's GPS or a router's "home" wins. For an answer that always names the room, PadSpan adds its own intent. It does nothing until you add sentences for it. Save this as config/custom_sentences/en/padspan.yaml and restart Home Assistant (or reload it from the Assist debug page):

language: "en"
intents:
  PadSpanWhereIs:
    data:
      - sentences:
          - "which room is {padspan_person} in"
          - "what room is {padspan_person} in"
          - "where in the house is {padspan_person}"
lists:
  padspan_person:
    wildcard: true

Intent: PadSpanWhereIs. Slots: padspan_person, name.

What it answers, in English:

  • "I don't know anyone called <name>."
  • "<name> is away."
  • "I don't know which room <name> is in right now."
  • "<name> is probably in the <room>."
  • "<name> is in the <room>."

"probably" when the room's room_confidence is under 0.5.

The name is the device's PadSpan name ("Alex"). It also matches a name that starts with it ("Alex's Phone", "Alex Watch"); with several, it picks the one heard most recently. You don't need to expose anything to Assist. The intent only reads PadSpan's current room and changes nothing. The answers are in English. More on what Home Assistant's own sentences do: Ask Assist where someone is.

MQTT (experimental)

With Enable experimental MQTT publishing ticked (Manage → HA Entities → MQTT Publishing; off unless ticked) and Home Assistant's MQTT integration set up, PadSpan also publishes each named device after every poll, retained. Here <device> is the name in lower case with spaces as _. The topics may change in a later version.

TopicHolds
padspan/devices/<device>/stateJSON: room, rssi, age_s, home, room_confidence
padspan/devices/<device>/areaThe room, not_home or unknown, as on the area sensor.
padspan/devices/<device>/distanceThe distance in metres. Not sent while away.

Three automations

Each one is a whole automation: paste it into a new automation's Edit in YAML. The names are examples; use your own entity ids.

A light on when Alex walks into the kitchen, only when PadSpan is fairly sure of the room:

alias: Kitchen light for Alex
trigger:
  - platform: state
    entity_id: sensor.alex_phone_area
    to: Kitchen
condition:
  - condition: numeric_state
    entity_id: sensor.alex_phone_area
    attribute: room_confidence
    above: 0.6
action:
  - action: light.turn_on
    target:
      entity_id: light.kitchen

The state is the room's name as Home Assistant has it, with its capitals.

A notice when the car keys leave the house:

alias: Car keys left
trigger:
  - platform: event
    event_type: padspan_device_departed
    event_data:
      label: Car keys
action:
  - action: notify.notify
    data:
      message: "The car keys have left the house."

The event comes once the keys have gone unheard for the away timeout (5 minutes unless you changed it in Settings → Tracking → Rooms and timing → Home/Away Timeout).

Arm the alarm while Vacation Mode runs:

alias: Alarm with Vacation Mode
trigger:
  - platform: state
    entity_id: binary_sensor.padspan_vacation_mode
    to: "on"
action:
  - action: alarm_control_panel.alarm_arm_away
    target:
      entity_id: alarm_control_panel.house
