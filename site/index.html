What's new

The releases since v0.21, in plain terms

If you installed PadSpan earlier this year and left it alone, a lot has changed underneath — and there is a reason you may not have heard about any of it. See the full changelog for every entry.

If you are on the stable channel and think you are current, check again. The update check built into the integration reported v0.21.13 as the latest stable right up until 23 August 2026, long after newer stable releases existed. That was a fault at my end, not at yours. It is fixed, and cutting a release now publishes the version manifest as part of the process, so it cannot drift like that again.
v0.38.0 Beta channel 25 August 2026

A map’s placement is now stored once, in metres. Four bugs that looked separate turned out to be the same one, and this removes the room they lived in rather than patching each.

  • Trimming, re-aligning or re-mastering a plan can no longer skew the house. A map’s position used to be written down twice, in two different units, and any operation that updated one copy and not the other left the two disagreeing. There is one copy now, so that disagreement has nowhere to exist.
  • Two live errors died with it. Calibration and Traceback were applying a map’s horizontal scale to the vertical axis, which on a trimmed reference map drew an object up to ten metres from where it actually was. Nothing in the interface showed that anything was wrong.
  • Point Align stops squashing a map onto a differently-shaped one (v0.37.1). Aligning a plan onto a map with a different aspect ratio came out compressed by exactly the ratio between the two pictures.
  • Plans can be genuinely skewed, not just moved and scaled. A scan that is slightly sheared — a photograph of a paper plan, most often — can now be described exactly instead of approximately.
  • There is no “master map” to lose any more. The star that marked one plan as the anchor for all the others is gone; every map now carries its own position in metres, so nothing breaks when it is changed.
  • Restoring a backup no longer writes one map’s alignment onto another. Restores matched maps by name, so a backup containing “Main Floor” would overwrite the alignment of any existing map with that name.

On the beta channel while the conversion is proven on real installs. It rewrites how every map records its position, so it takes a backup of every store before it starts and marks each map as it goes, so an interrupted run can be resumed rather than half-applied.

v0.37.0 Stable 23 August 2026
  • Changing the master map now moves the whole house at once. The relink rebuilt every map's placement from fields the renderer ignores whenever a map had been placed by Point Align, and it only moved maps that referenced the old master — the rest were left behind in the old frame. It is now one exact step over the transform actually being drawn, so hand-placed and Point-Aligned maps move together.
  • The usage report stopped reporting things that were always zero. Three fields could never be anything but zero by construction, and panel events that happened before the settings loaded were silently dropped — including the exact class of error the report was added to catch. Three switches that were reported as features turned out to have no implementation at all and are gone.
  • Releases publish their own version manifest, which is what closes the stale-update-check problem above.
v0.36.0 – v0.36.919 – 21 August 2026
  • Trimming a floor plan no longer skews the house. A crop re-derived only one of the two stored copies of a map's placement, so rooms drew correct across and wrong down by exactly the map's aspect error.
  • A scanner's name is no longer part of another scanner's. With proxies named btproxy, btproxy_kitchen and btproxy_livingroom, assigning an area to one moved the others with it.
  • A device that is outside and heard by nothing no longer stops the poll. This fixes a whole-install freeze introduced in v0.36.1 — if you are on that version, upgrade past it.
  • The solver stopped claiming certainty it did not have, phantom devices from abandoned addresses are gone, and one device's failure can no longer take the whole poll down with it.
v0.35.0Stable18 August 2026
  • The edition and licence model landed — see Editions below.
  • Private BLE keys tell the truth. A value that is really an iBeacon UUID is refused instead of silently resolving nothing forever, and a fingerprint bridge is no longer treated as an identity.
  • An opt-in usage report, off by default — counts, versions and flags only, never addresses, keys, names or coordinates. There is a Preview what would be sent button that shows you the exact payload.
  • The Bluetooth view was restyled into one visual language across all five sub-tabs.
v0.34.0 – v0.34.1116 – 18 August 2026
  • Multi-floor actually works. The floor list never reached the positioning code, so a multi-storey house was scored as a single storey. The panel looked right the whole time because it reads the Home Assistant floor registry live, which is exactly why this survived as long as it did. If you gave up on PadSpan because it put people on the wrong floor, this is the fix.
  • Geometry moved off the picture. Rooms, scanners, walls and lights are stored in metres in their own model rather than as coordinates on the image you uploaded. Re-crop or replace a plan and nothing moves.
  • Scanners carry a real mounting height and floors carry a real elevation, so a cross-floor decision finally has something to separate storeys by. Walls are RF barriers with an attenuation value rather than decoration.
  • RSSI Vector Capture — record what every scanner heard for every tracked device, poll by poll, marking rooms as you walk. Export the session and replay that same walk against different settings instead of walking it again. Off by default.
  • Auto-calibration writes fingerprints from stationary beacons, so there is less walking around the house with a phone in your hand.
v0.22.04 August 2026
Forensics arrived as the first Pro feature, along with light placement and map origin anchoring.
Why PadSpan

A complete tracking workstation, not just a sensor

Most BLE presence integrations give you a config flow and a sensor. PadSpan gives you a floor plan editor, room boundary polygons, 3D isometric maps, walk-around calibration, follow mode with email alerts, a training hub, and a full sample/demo mode — so you can explore every feature before plugging in hardware.

It works with the BLE scanners you already have. Home Assistant Bluetooth proxies and Bermuda proxies are picked up directly. ESPresense nodes arrive over MQTT, which you switch on in Manage → ESPresense MQTT and which needs Home Assistant's MQTT integration configured. No custom firmware. No cloud dependency. Everything runs locally.

Lighting

Your lights on the same floor plan

PadSpan already knows the shape of your house in metres — the rooms, the floors, the walls. Mapping → Lights puts your Home Assistant lights on that same plan, so you can see and switch them where they actually are instead of hunting through a list of entity names.

Free, in every install No key

  • The lighting map — rooms and floors drawn from your real geometry
  • One marker per light, in the room it belongs to
  • Click a light to switch it
  • Never hidden: the Lights tab is visible whether or not you hold a key

With a key

  • Place each light exactly where it hangs, in metres
  • Fixture shapes and sizes — a strip is not a spot
  • WLED devices, with their own controls
  • Showcase mode and Fit room

Placement is unlocked by a PadSpan Pro key today. Nothing you have drawn is ever touched by the gate — enter a key and every placement returns exactly as it was, and a lapsed licence still reads and exports everything you built.

Editions

Four programs, two dials

There is one codebase. Which edition you download decides what you can see; what your key says decides what you can edit. A Pro key typed into any edition unlocks everything that edition can show, so you never have to work out which key goes with which download.

Phone & Watch Tracking

The hardest problem in BLE presence — solved several ways

Phones rotate their Bluetooth address every ~15 minutes specifically to prevent tracking. PadSpan offers multiple paths depending on your device:

DeviceEasiest MethodWhat You Need
Android phoneHA Companion App iBeaconInstall app, enable BLE Transmitter. Done.
iPhone / iPadIRK via irk-captureSpare ESP32, flash irk-capture, pair once, paste IRK
Apple WatchIRK via irk-captureSame as iPhone — pair watch to irk-capture ESP32
Tile / ChipoloAutomatic (iBeacon)Stable UUID — just works, tag once
AirTagProbabilistic (experimental)Apple Classification + MAC Rotation Bridging
SmartTagProbabilisticSame as AirTag — MAC Rotation Bridging

The IRK extraction workflow is built on Derek Seaman's irk-capture — an ingenious ESP32 tool that makes practical phone tracking in Home Assistant possible without rooting devices or owning a Mac.

Installation

Up and running in minutes

Requirements: Home Assistant 2024.1+, at least one BLE scanner (ESPresense, Bermuda proxy, or HA Bluetooth proxy), and HACS (recommended).

Via HACS (recommended)

  1. Open HACS in your Home Assistant instance
  2. Add gbroeckling/padspanHA as a custom repository (Integration type)
  3. Search for and install PadSpan HA
  4. Restart Home Assistant completely
  5. Add the integration: Settings → Devices & Services → Add Integration → PadSpan HA

Quick Start

  1. Open the PadSpan HA panel in the sidebar
  2. The onboarding wizard guides you: upload a map, set scale, draw rooms, place scanners, calibrate
  3. Try Sample mode to explore every feature with demo data
  4. Switch to Live mode — your BLE scanners are auto-discovered
  5. Tag your devices and start tracking

Development

One developer, strong opinions

PadSpan HA is built by Garry Broeckling — a 30+ year veteran of coding and scripting who has never claimed to be a fast typist. All architecture, product decisions, testing, and releases are human-directed. Implementation is AI-assisted using Claude by Anthropic, which accelerates the write–test–ship cycle considerably. Think of it as one developer with strong opinions and a very patient pair-programming partner.

The result: a solo project that ships features at a pace that would normally require a team — without compromising on quality, security, or code review.

PadSpan Pro

Pro features, one key — the core stays free

PadSpan HA is and remains free, open-source (GPL) software. Pro is an optional license that unlocks advanced features inside the same integration — no separate install, no cloud dependency, all data stays on your Home Assistant instance.

What Pro unlocks today

  • Forensics — search which BLE devices were near your scanners in any time window. Recorded presence sessions (dwell time, peak signal, per-scanner detail) plus lower-confidence "possible" matches, with CSV export.
  • Opt-in and privacy-guarded: off by default, explicit enable confirmation, configurable retention (7–90 days), recordings never leave your instance.
  • Light placement — place each light exactly where it hangs, with fixture shapes and sizes, WLED support, Showcase and Fit room. See Lighting.
  • More Pro features will join under the same key.
